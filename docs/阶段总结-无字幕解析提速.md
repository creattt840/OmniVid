# 阶段总结 — 无字幕解析性能优化（2026-06-16）

> 状态：**已完成，可验收**

## 一、背景与目标

无字幕视频的 AI 分析路径（`POST /api/analyze`）此前耗时可达数分钟，瓶颈主要在：

1. B站 / 抖音下载整段视频而非纯音频
2. Whisper `beam_size=5` 在 CPU 上推理偏慢
3. parse → analyze 重复拉取平台元数据 / yt-dlp `extract_info`
4. 首次请求冷启动加载 Whisper 模型

本次在不改产品流程的前提下，显著缩短无字幕转写 wall-clock 时间。

## 二、已完成功能

### 2.1 下载链路瘦身

| 平台 | 优化前 | 优化后 |
|------|--------|--------|
| B站 | 固定 qn=16 下载 360p 整段视频 | 优先 DASH 纯音频轨；回退渐进流 + FFmpeg 抽音 |
| 抖音 | 下载完整 MP4 | 下载后 FFmpeg 抽成 16kHz 单声道 MP3 |
| YouTube / 通用 | 已用 bestaudio | 复用 parse 阶段缓存的 `extract_info`，避免二次拉元数据 |

新增 [`backend/app/services/media/audio_extract.py`](../backend/app/services/media/audio_extract.py)、[`bilibili._get_audio_url()`](../backend/app/services/video/bilibili.py)。

### 2.2 Whisper 参数与预热

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `WHISPER_BEAM_SIZE` | `1` | 推理加速（可设 `5` 恢复更高精度） |
| `WHISPER_WARMUP` | `true` | 启动时后台预加载模型，消除首用户冷启动 |

服务启动日志可见：`Whisper 模型预热完成: small`。

### 2.3 元数据缓存（TTL 10 分钟）

新增 [`metadata_cache.py`](../backend/app/services/video/metadata_cache.py)：

- `parse` 阶段写入 B站 view、抖音 item_info、yt-dlp info
- `analyze` / 字幕拉取 / Whisper 转写优先读缓存，减少重复 API 与 yt-dlp 调用

### 2.4 体验与可观测性

- 前端 `VideoSummary` 根据视频时长显示更明确的转写等待提示
- `transcriber` 输出结构化耗时日志：`download_ms` / `whisper_ms` / `total_ms`

## 三、环境配置

`backend/.env` 新增（见 `.env.example`）：

```env
WHISPER_BEAM_SIZE=1
WHISPER_WARMUP=true
```

生产环境同步更新 `deploy/env.production.example` 后重启 uvicorn。

## 四、预期效果（估算）

10 分钟 B站无字幕视频（2 核 CPU）：

| 环节 | 优化前 | 优化后（估） |
|------|--------|--------------|
| 媒体下载 | ~60–120s | ~10–20s |
| Whisper ASR | ~120–180s | ~40–70s |
| 冷启动 | 首用户 +10s | 0（预热） |
| **合计** | **~3–5 min** | **~1–1.5 min** |

## 六、如何验收

1. 配置 `.env` 中 `WHISPER_BEAM_SIZE=1`、`WHISPER_WARMUP=true`，重启后端
2. 各平台选 1 条**无字幕**视频，对比优化前后 `POST /api/analyze` 耗时
3. 查看后端日志中的 `download_ms` / `whisper_ms`
4. 有字幕视频仍走 subtitle 路径，不触发 Whisper
5. 纯音乐视频仍被质量门控拒绝

## 七、回退方式

- 精度不满意：`WHISPER_BEAM_SIZE=5`
- 关闭预热：`WHISPER_WARMUP=false`
- B站 DASH 音频不可用时会自动回退 durl + FFmpeg，功能不退化
